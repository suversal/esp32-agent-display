# Vibe Island 内容显示

2026-10-15，用户要求把电脑上 Vibe Island 已显示的会话信息同步到 ESP32。此前摘要只保留“执行命令”“读取文件”等分类，无法辨认具体对话；这次直接读取本机已有的内容缓存。

## 数据与状态

- 缓存：~/Library/Application Support/vibe-island/session-terminals.json。实际核对字段包括 source、cwd、status、customTitle、firstUserMessage、lastUserMessage、lastAssistantMessage、currentTool、lastActivityAt。
- lastActivityAt 为 Apple 2001 epoch，转换到 Unix 时间后计算活动年龄。Codex 的 codex- 前缀与 thread ID 归一，Claude source 映射为 claude-code。
- 每秒检查文件变化，最多读取 1 MiB / 128 个条目。只保留短摘录和元数据；不使用 lastAssistantMessageFull，不扫描历史记录。部分写入、缺失或格式错误保留最后一个有效缓存，并受活动过期限制。
- 同一 key 优先使用新鲜的原生 hooks 状态与项目别名，再补标题、提问、回复和工具名。原生运行状态超过 15 分钟未更新，且缓存活动时间更晚时，仅用已知 processing / running_tool / waiting_for_input 校正显示。缓存不会清除真实授权等待、确认提醒或增加声音序号。缓存独有的会话按已知状态显示，不生成授权/完成提醒。
- 完整显示状态按状态和最近活动排序。分页按待处理等待、运行中、已完成、空闲分组，同一状态内保持稳定；状态变化会调整分组，新运行会话不会被旧完成卡片挡在后面。安静等待输入不要求心跳。仅缓存或用较新缓存校正的卡片显示“刚刚 / Nm前 / Nh前”，不伪造整轮耗时。
- /state 的 snapshot 保留原生状态，display_snapshot 返回带内容的完整显示状态，device_connections 返回已握手设备数量和固件版本。0.5.0 协商分页后，/ws 每页发送三张内容卡片或四张紧凑卡片；旧设备继续收到前四项。device_pages 提供页码和轮播状态。

提问、回答摘录只在本项目的内存和设备连接中使用，不进入 Engine.export、bridge 状态文件或日志。Vibe Island 原有文件由该应用管理，本项目仅只读。可通过 vibe_island_path = "" 禁用。

## 0.4.0 浅色阅读布局

2026-10-15，移除固定大标题，仓库与会话标题合并为一行。状态、工具和耗时独立为紧凑的一行，下方专门显示可换行的提问与回复。三会话时每卡最多四行对话，单、双会话自动扩大阅读区域；授权只用静态边框标记，保持白底黑字。

摘录从 100 字符扩至 240 字符，标题仍限 100；设备各对话字段容量改为 768 字节，支持完整的 240 个中文字符和截断标记。凭据遮盖、内存使用和不落盘约定保持不变，不读取完整历史。旧设备仍可按旧容量截断读取，协议版本保持 v2。

79 项桥接测试、12 种真实 C 渲染场景通过。应用 1,588,048 字节，Flash 写入校验成功，NVS 未写入。设备以 fw=0.4.0 重连，实际缓存的回复摘录达到 240 字符。用户确认“显示正常，清楚多了”。固件模拟图及本机可切换预览只使用示例内容，不保存真实对话。

## 0.5.0 分页与陈旧状态修复

2026-10-15，新增每 20 秒自动轮播、BOOT 短按翻页后停留 60 秒、按住约 1 秒松开暂停/恢复。原来的长按约 2 秒切换静音保留。有待确认提醒时短按优先确认，新的授权提醒定位到对应页并暂停自动翻页。每连接独立维护导航状态，只保留会话 key，不持久化页面或增加摘录存储。用户已确认自动轮播、短按翻页以及暂停/恢复正常。

照片中的“可能已中断”来自超过 15 分钟没有原生 hook 更新后的推断，并不证明任务中断。现场核对时，同一 ESP32 会话两秒前仍有缓存活动，另两个 Codex 会话的较新缓存为等待输入，但旧 hook 状态遮住了它们。现在缺少新活动时显示“状态待更新”；同一会话有更晚的已知缓存状态时校正陈旧运行状态，真实等待与提醒不受影响。另补充实际观察到的 running_tool 状态，按运行中显示。缓存本身也过期时保留不确定标记。

90 项桥接测试通过，覆盖 128 会话的 43 页、活动更新不打乱页序、20/60 秒定时、独立设备、暂停、删除会话、提醒定位和确认、旧设备兼容，以及陈旧运行状态与较新缓存的取舍。17 种真实 C 渲染场景及共享按键逻辑通过 ASan/UBSan。0.5.0 已烧录校验并重连，物理验收与恢复边界见 ../../agent_display/verification.md。
